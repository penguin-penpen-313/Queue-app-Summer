# 夏祭り 順番待ちアプリ

配信コメントを読み取って順番待ちの列を自動で管理するツール。テーマは夏祭り＋花火。

## 使い方

1. 全ファイルを同じフォルダに置いてWebサーバーに配置（GitHub Pages等）。
   - `file://` では動きません。ローカル確認は `python3 -m http.server` 等で。
2. 動作確認は `test.html` を開き、疑似コメントを流す。**このタブ単体で動作する。**
3. 本番は管理パネルを開いておくと、そこがコメント処理役になる（優先度が最も高い）。

### コメント処理エンジンについて

順番待ち画面・管理パネル・テストページのどれもエンジンを内蔵している。
同時に複数開いても、**処理するのは1タブだけ**（リーダー選出）。優先度は
管理パネル(10) > テストページ(5) > 順番待ち画面(1)。
リーダーのタブを閉じると、他のタブが数秒で自動的に引き継ぐ。

テストページ左下のバッジで、どちらが処理役か確認できる。

## うまく動かないとき

| 症状 | 確認 |
|---|---|
| コメントを送っても順番待ちに反映されない | テストページか管理パネルか順番待ち画面のいずれかを開いているか（どれか1つがコメント処理役になる） |
| 他の端末に出ない／permission-denied | 管理パネルの **「🔍 同期をテスト」** を押す。読み取り・書き込みのどちらが失敗しているか分かる。対処は `FIREBASE-セキュリティ.md` |
| 同上 | テストページの JUDGE 欄が「列の最後尾に追加」になっているか。「何もしない」ならキーワード不一致 |
| 同上 | ブラウザのサイトデータ（localStorage）がブロックされていないか。プライベートモードや厳格なトラッキング防止で動かない場合がある |
| ファイルが読めない | `config.js` `queue-core.js` `theme.js` `theme.css` が同じフォルダにあるか（DevToolsのNetworkタブで404を確認） |
| 状態を初期化したい | 管理パネルの「全リセット」、またはブラウザのサイトデータ削除 |

## 動作ルール

- コメント本体が **「予約！」** または **「join!」**（config で変更可）→ 列の最後尾に追加
- 1行目に **「〇〇さんがコラボ配信に参加しました」** → その人を **NOW** に大きく表示
  - 順番待ちにいれば順番に関係なく列から抜けてNOWへ
  - すでにNOWの人がいる場合は **NOWに並べて表示**（最大4人・config可変）
  - 列にいない人が参加した場合もゲストとしてNOWに表示
- 1行目に **「〇〇さんがコラボ配信を退出しました」** → NOWから外れ、次の人がNEXTに
- コメントに **「〜(1000C)×3をあげました」** → コイン数×個数の発数だけ花火（下記）
- すでに並んでいる人の再「予約！」は無視
- GUIからの予約機能なし。手動追加・削除・並べ替えは管理パネルのみ

## 管理パネルのURLについて

ファイル名にランダムな24桁（`admin-22fe99702897e3546a7d23f3.html`）を使用。
どのページからもリンクしておらず、HTMLを読んでも推測できない。

- 変更したい場合はファイル名のランダム部分を任意の文字列に差し替えるだけ
- 検索エンジン避けに `noindex` を設定済み
- ディレクトリ一覧が公開されるサーバーでは、一覧表示を必ずオフにすること

## REALITYのコメントを取り込む（本番用セットアップ）

REALITYのコメント画面は **別ドメイン（reality.app）のJavaScript描画ページ** なので、
GitHub Pages 側のJavaScriptからは直接読めない（ブラウザの同一オリジンポリシー）。
そこでコメント画面側に小さなスクリプトを常駐させ、順番待ちアプリへコメントを転送する。

### 手順

**→ 詳しくは `セットアップ手順.md`**

1. Chromeに **Tampermonkey** 拡張をインストール
2. 「新規スクリプトを作成」→ 中身を全消し → `reality-bridge.user.js` を貼り付け → Ctrl+S
3. **`test.html` を開いて確認**（配信不要）。
   上部に「✅ 橋渡しスクリプトは動いています」と出れば導入成功
4. 本番は管理パネルの「コメント画面のURL」欄にURLを貼って
   「REALITYコメント画面を開く」

### 配信ごとにURLが変わる件

REALITYのコメントURLは配信を始めるまで発行されない。
そのためスクリプトは **reality.app の全ページ**（`@match https://reality.app/*`）で動くようにしてある。
URLを事前に設定する必要はなく、配信開始後に管理パネルの入力欄へ貼るだけでよい
（貼った値はブラウザに保存される）。自分でURLを開いた場合は、
パネルの「順番待ちアプリを開いて接続」を押せば繋がる。

### テスト＆動作確認ページ（test.html）

橋渡しの導入判定とテストコメントを1ページにまとめてある。配信を始めずに全部確認できる。

- 上部で**ユーザースクリプトが入っているか**を判定（✅/❌）
- **送信の経路**を選べる
  - **橋渡し経由** … REALITYと同じ形のJSONをスクリプトへ流す。**本番とまったく同じ道すじ**
  - **直接** … スクリプトを通さずアプリへ渡す。文言や花火だけ見たいとき
  - スクリプトの有無で自動的に切り替わる（見つからなければ「直接」）
- 「予約！」→ 列に並ぶか／コラボ参加・退出 → NOWが切り替わるか
- ギフト → 花火の発数が正しいか（コイン数 × 個数）
- 右側に本番と同じ構造の模擬コメント欄と、順番待ちの現在の状態
- DOMモードの練習（折りたたみの中にREALITY風のコメント欄）

### 仕組み

スクリプトはコメント画面の通信（WebSocket / EventSource / fetch / XHR / Worker）を
すべて監視し、受信したコメントを `postMessage` で順番待ちアプリのウィンドウへ転送する。
受け取る側は `config.js` の `comment.bridgeOrigins`（既定 `https://reality.app`）
と自分自身のオリジンからのメッセージだけを受け付ける。

パネルのスタイルはJavaScriptから直接あてているので、
ページ側のCSP（コンテンツセキュリティポリシー）が厳しくても表示される。
ページがDOMを作り直してパネルが消えた場合も、2秒以内に自動で戻る。

### うまく拾えないとき

パネルは3タブ。

- **接続**：接続状態とログ、テストコメント送信
- **診断**：通信の一覧と生データ。「レポートをコピー」で全部まとめてコピーできる
- **DOM**：通信から拾えない場合に、画面の文字から直接拾う設定

配信中に「診断」→「更新」で受信が0のままなら、
**レポートをコピー**した内容を送ってもらえれば形式に合わせて調整できる。

DOMから拾う場合は「DOM」タブ →「コメント欄の候補を探す」→
コメント内容が「例:」に出ている候補をクリック。

## 配信コメントURLの設定

配信が始まってコメント表示URLが分かったら `config.js` の `comment` を書き換える。

```js
comment: {
  mode: 'fetch',                   // 'test' | 'fetch' | 'iframe' | 'onecomme'
  url: 'https://.../comments',     // ← 「特定のURL」
  listSelector: '#commentList',    // コメントが積まれる親要素
  itemSelector: '.comment-item',   // コメント1件の要素
}
```

| mode | 用途 | 条件 |
|---|---|---|
| `bridge` | REALITYのコメント画面から転送（初期値）／テストページからも受信 | ユーザースクリプト |
| `fetch` | URLを定期取得してHTML解析 | 同一オリジン or CORS許可 |
| `iframe` | iframeで読み込みDOM監視 | 同一オリジン |
| `onecomme` | わんコメ等のローカルWebSocket | わんコメ起動中 |

ブラウザの制約上、**別ドメインのページは直接読めない**。別ドメインの場合は
わんコメなどのコメントビューアを経由するか、コメントを中継する仕組みが必要。
どのモードでも判定ロジック（予約！／参加／退出）は共通なので、
取得部分だけ差し替えれば動く。

## ギフト → 花火

コメントに **「〜(1000C)×3をあげました」** が現れると、
**コイン数 × 個数** の発数だけ花火を打ち上げる。個数が1のときは `×n` が付かない
（「〜(1000C)をあげました」＝1000発）表記にも対応済み。

REALITYのギフト行は**名前欄が空で、本文1行だけ**で届く。

```
お中元 名前入りキャンプタワー(10000C)をあげました
└贈り主┘ └───ギフト名───┘ └コイン┘        → 10,000発

ｴﾘｵｯﾄ&ｴﾝｼﾞｪﾙちゃん🪽👼⭐️ 小さなアヒルさん(100C)×8をあげました
└──────贈り主──────┘ └─ギフト名─┘ └コイン┘└個数┘  → 800発
```

ギフト名は `(1000C)` の直前の1語なので、そこで区切って贈り主を取り出している。

同じギフトが複数の経路（WebSocketとfetchなど）から二重に届くことがあるため、
**8秒間は同じギフトを1回として数える**（`config.js` の `gift.dedupeMs`）。
以前 10000C 1個で30000発になっていたのはこれが原因。

### 発数と演出

発数が多いほど派手になる。1発〜10000発（上限）の間で連続的に変化する：

| 発数 | 所要時間 | 同時に上がる数 | 実際に描く玉 | 1玉の粒 |
|---:|---:|---:|---:|---:|
| 1 | 0.9秒 | 1 | 1 | 40 |
| 8 | 3.6秒 | 2 | 8 | 35 |
| 100 | 10.6秒 | 5 | 100 | 29 |
| 800 | 14.7秒 | 7 | 800 | 24 |
| 3,000 | 17.5秒 | 9 | 900 | 21 |
| 10,000 | 20.0秒 | 10 | 900 | 18 |

発数が非常に多いときは玉を1つずつ全部描かず、**大きな玉を少なめに**置き換えて
負荷を抑える（それでも派手さは保たれる）。花火の最中も順番待ちの表示は
止まらずに更新される。

### 長さを変えたいとき

`config.js` の `fireworks` を書き換える。

| 項目 | 意味 | 既定 |
|---|---|---|
| `maxDurationMs` | **最大発数のときの長さ**（★ここで全体の長さが決まる） | 20000（20秒） |
| `minDurationMs` | 1発のときの長さ | 1200 |
| `maxSimul` | 同時に上がる玉の数の上限 | 10 |
| `maxRenderShells` | 実際に描画する玉の上限（負荷対策） | 900 |
| `maxParticles` | 画面に同時に存在する粒の上限（負荷対策） | 1800 |
| `opacity` | 花火の濃さ（下げると順番待ちが読みやすい） | 0.85 |

例：一番大きなギフトでも10秒で終わらせたい → `maxDurationMs: 10000`。
重いと感じる → `maxRenderShells` と `maxParticles` を下げる。

上限発数は `gift.maxShells`（既定10000）。

## データの保存先（他の端末からも見える）

Firestore に保存する。順番待ち画面のURLを知っていれば、**別のPC・スマホ・
別のブラウザからでも同じ順番待ちが見える**（リアルタイム更新）。

Firebase プロジェクト **`queue-summer`**（夏祭り専用）を使う。
コレクション名は `matsuri-rooms`、ドキュメントは `sync.roomId`（既定 `summer-matsuri`）の1件だけ。

初回は Firebase 側の準備が必要：

1. Firestore Database を **本番環境モード** で作成（テストモードは30日で切れる）
2. 同梱の `firestore.rules` を「ルール」タブに丸ごと貼って公開
3. 管理パネルの「🔍 同期をテスト」で読み書き両方OKを確認

詳しくは `FIREBASE-セキュリティ.md`。

### Firestore のセキュリティルール（要設定）

同梱の **`firestore.rules`** を、Firebaseコンソール（プロジェクト `queue-summer`）→
Firestore Database → 「ルール」タブに丸ごと貼り付けて公開する。

書き込めるのは `matsuri-rooms/summer-matsuri` の1件だけで、
フィールドの種類と配列の長さも検証している。
公開後は管理パネルの右上が「全端末と同期中」になるか必ず確認すること。

### GitHubの「Google API Key」警告について

`config.js` に含まれる `apiKey` は **Firebase の公開識別子** であり、秘密鍵ではない。
ブラウザで動く以上ソースに必ず含まれるもので、Googleも
[公式に「コードに含めても安全」と明記](https://firebase.google.com/docs/projects/api-keys)している。
GitHubのアラートは `Won't fix` で閉じてよい。

データを守るのはキーの秘匿ではなく、次の2つ：

1. **Firestoreセキュリティルール**（上記 `firestore.rules`）
2. **APIキーの制限** … Google Cloud Console で「ウェブサイトの制限」に
   `https://penguin-penpen-313.github.io/*` を設定

詳しい手順は **`FIREBASE-セキュリティ.md`**。

### このブラウザ内だけに戻したいとき

`config.js` の `sync.backend` を `'local'` にすれば、サーバーを使わず
同じブラウザ内のタブだけで同期する（以前の動作）。

### 同期状態の見方

- 順番待ち画面：上部に「同期中」の緑バッジ
- 管理パネル：右上に「全端末と同期中」、右パネルに「同期の状態」

### permission-denied / 同期エラーが出たら

管理パネルの **「🔍 同期をテスト」** を押す。読み取りと書き込みを別々に試し、
どちらが失敗しているかと原因の見当を表示する。

| 結果 | 原因 |
|---|---|
| 読み取りNG / 書き込みNG | ルールが効いていない。コレクション名かFirestore自体を確認 |
| 読み取りOK / 書き込みNG | ルールの書き込み条件に合っていない |

詳しい手順は `FIREBASE-セキュリティ.md`。

## config.js で変えられるもの

- タイトル・サブタイトル・案内文・敬称
- 並ぶキーワード（複数可・完全一致／部分一致）
- コラボ参加／退出メッセージの雛形（`{name}` が名前）
- NOW の最大人数、NEXTの後ろに表示する人数
- ラベル文言（NOW / NEXT / 順番待ち など）
- 配色（夜空・提灯・花火の色）
- 花火の演出（間隔・同時数・最長時間・上限発数）
- ギフト判定の正規表現
- 保存先（Firestore / このブラウザ内のみ）と部屋の名前
