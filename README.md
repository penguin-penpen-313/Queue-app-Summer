# 夏祭り 順番待ちアプリ

配信コメントを読み取って順番待ちの列を自動で管理するツール。テーマは夏祭り＋花火。

## ファイル構成

| ファイル | 役割 | 公開範囲 |
|---|---|---|
| `index.html` | 順番待ち画面（NOW / NEXT / このあと） | **誰でも閲覧可** |
| `admin-22fe99702897e3546a7d23f3.html` | 管理パネル＋コメント監視エンジン | **URLを知る者のみ** |
| `test-comments.html` | テスト用の疑似コメント配信環境 | 手元確認用 |
| `reality-bridge.user.js` | REALITYコメント画面用のユーザースクリプト（Tampermonkey） | ブラウザに登録 |
| `config.js` | すべての設定（文言・キーワード・色・取得方式） | — |
| `queue-core.js` | 状態管理・コメント解析・取得アダプタ | — |
| `theme.js` / `theme.css` | 配色適用・花火エフェクト・共通スタイル | — |

## 使い方

1. 全ファイルを同じフォルダに置いてWebサーバーに配置（GitHub Pages等）。
   - `file://` では動きません。ローカル確認は `python3 -m http.server` 等で。
2. 動作確認は `test-comments.html` を開き、疑似コメントを流す。**このタブ単体で動作する。**
3. 本番は管理パネルを開いておくと、そこがコメント処理役になる（優先度が最も高い）。

### コメント処理エンジンについて

順番待ち画面・管理パネル・テストページのどれもエンジンを内蔵している。
同時に複数開いても、**処理するのは1タブだけ**（リーダー選出）。優先度は
管理パネル(10) > テストページ(5) > 順番待ち画面(1)。
リーダーのタブを閉じると、他のタブが数秒で自動的に引き継ぐ。

テストページ左下のバッジで、どちらが処理役か確認できる。

## うまく動かないとき

| 症状 | 確認 |
|---|---|
| コメントを送っても順番待ちに反映されない | テストページと順番待ち画面を **同じブラウザの別タブ** で開いているか。別デバイス・別ブラウザ・シークレットウィンドウとは同期しない |
| 同上 | テストページの JUDGE 欄が「列の最後尾に追加」になっているか。「何もしない」ならキーワード不一致 |
| 同上 | ブラウザのサイトデータ（localStorage）がブロックされていないか。プライベートモードや厳格なトラッキング防止で動かない場合がある |
| ファイルが読めない | `config.js` `queue-core.js` `theme.js` `theme.css` が同じフォルダにあるか（DevToolsのNetworkタブで404を確認） |
| 状態を初期化したい | 管理パネルの「全リセット」、またはブラウザのサイトデータ削除 |

## 動作ルール

- コメント本体が **「予約！」** または **「join!」**（config で変更可）→ 列の最後尾に追加
- 1行目に **「〇〇さんがコラボ配信に参加」** → その人を **NOW** に大きく表示
  - 順番待ちにいれば順番に関係なく列から抜けてNOWへ
  - すでにNOWの人がいる場合は **NOWに並べて表示**（最大4人・config可変）
  - 列にいない人が参加した場合もゲストとしてNOWに表示
- 1行目に **「〇〇さんがコラボ配信を退出」** → NOWから外れ、次の人がNEXTに
- すでに並んでいる人の再「予約！」は無視
- GUIからの予約機能なし。手動追加・削除・並べ替えは管理パネルのみ

## 管理パネルのURLについて

ファイル名にランダムな24桁（`admin-22fe99702897e3546a7d23f3.html`）を使用。
どのページからもリンクしておらず、HTMLを読んでも推測できない。

- 変更したい場合はファイル名のランダム部分を任意の文字列に差し替えるだけ
- 検索エンジン避けに `noindex` を設定済み
- ディレクトリ一覧が公開されるサーバーでは、一覧表示を必ずオフにすること

## REALITYのコメントを取り込む（本番用セットアップ）

REALITYのコメント画面は **別ドメイン（reality.app）のJavaScript描画ページ** なので、
GitHub Pages 側のJavaScriptからは直接読めない（ブラウザの同一オリジンポリシー）。
そこでコメント画面側に小さなスクリプトを常駐させ、順番待ちアプリへコメントを転送する。

### 手順

1. Chromeに **Tampermonkey** 拡張をインストール（Chromeウェブストアで「Tampermonkey」）
2. Tampermonkeyのダッシュボード →「新規スクリプトを作成」→ 中身を全部消して
   `reality-bridge.user.js` の中身を貼り付け → 保存（Ctrl+S）
3. 管理パネルを開き、右上の **「REALITYコメントを開く ↗」** を押す
4. 開いたREALITYのコメント画面の右下に「順番待ち 橋渡し」パネルが出る。
   ● が水色で「接続中」なら準備完了
5. 配信を開始すればコメントが自動で流れ込む

コメント画面を直接開いてしまった場合は、パネルの
**「順番待ちアプリを開いて接続」** を押せば同じ状態になる。

### 仕組み

スクリプトはコメント画面の WebSocket（`wss://comment.reality.app`）をフックして、
受信したコメントを `postMessage` で順番待ちアプリのウィンドウへ転送する。
受け取る側は `config.js` の `comment.bridgeOrigins` に書かれたオリジン
（既定は `https://reality.app`）からのメッセージだけを受け付ける。

### うまく拾えないとき

REALITYの内部仕様は非公開のため、コメントのデータ形式が変わっている可能性がある。
パネルの「詳細設定・ログ」を開くと **直近の生データ（JSON）** が見えるので、
その中身を伝えてもらえれば対応するフィールド名に合わせて調整できる。

生データが空のまま（WS 0 のまま）の場合は、DOMから拾う方法に切り替える：

1. パネルの **「要素を選ぶ」** を押す
2. コメント1件分の枠をクリック → セレクタが自動設定され、DOM監視が始まる

## 配信コメントURLの設定

配信が始まってコメント表示URLが分かったら `config.js` の `comment` を書き換える。

```js
comment: {
  mode: 'fetch',                   // 'test' | 'fetch' | 'iframe' | 'onecomme'
  url: 'https://.../comments',     // ← 「特定のURL」
  listSelector: '#commentList',    // コメントが積まれる親要素
  itemSelector: '.comment-item',   // コメント1件の要素
}
```

| mode | 用途 | 条件 |
|---|---|---|
| `bridge` | REALITYのコメント画面から転送（初期値）／テストページからも受信 | ユーザースクリプト |
| `fetch` | URLを定期取得してHTML解析 | 同一オリジン or CORS許可 |
| `iframe` | iframeで読み込みDOM監視 | 同一オリジン |
| `onecomme` | わんコメ等のローカルWebSocket | わんコメ起動中 |

ブラウザの制約上、**別ドメインのページは直接読めない**。別ドメインの場合は
わんコメなどのコメントビューアを経由するか、コメントを中継する仕組みが必要。
どのモードでも判定ロジック（予約！／参加／退出）は共通なので、
取得部分だけ差し替えれば動く。

## データの保存先

ブラウザの localStorage ＋ BroadcastChannel（＋localStorageイベントの二重経路）。
サーバー不要で、同じPCの同じブラウザ内で複数タブ（管理パネル／順番待ち画面／
OBSブラウザソース）が即座に同期する。**別のPC・別のブラウザとは同期しない。**

観客のスマホにも同じ列を見せたい場合は、この方式では不可。順番待ち画面をOBSの
ブラウザソースとして配信画面に載せるか、保存先をFirestore等のサーバーに差し替える必要がある。

## config.js で変えられるもの

- タイトル・サブタイトル・案内文・敬称
- 並ぶキーワード（複数可・完全一致／部分一致）
- コラボ参加／退出メッセージの雛形（`{name}` が名前）
- NOW の最大人数、NEXTの後ろに表示する人数
- ラベル文言（NOW / NEXT / 順番待ち など）
- 配色（夜空・提灯・花火の色）
- 花火の頻度・呼び出し時の演出
